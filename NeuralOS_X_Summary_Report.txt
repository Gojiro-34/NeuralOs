1. PROJECT OVERVIEW
================================================================================

  NeuralOS X is a Mini Operating System Simulator built in C++17 for the
  CL-2006 Operating Systems Lab course (Spring 2026). It simulates core OS
  concepts including process management, CPU scheduling, memory management,
  inter-process communication (IPC), resource allocation, and deadlock
  detection — all running on a Linux/POSIX host via fork(), exec(), pipes,
  and pthreads.

  Usage:  ./NeuralOS_X <RAM_GB> <HDD_GB> <CORES>
  Example: ./NeuralOS_X 1 10 2

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  5.2  ADAPTIVE SCHEDULER  (scheduler.cpp — 280 lines)                  │
  └──────────────────────────────────────────────────────────────────────────┘

    Three-Level Multi-Level Queue (MLQ) Scheduling:
    ────────────────────────────────────────────────
      L0 (Reflex)     — Round Robin (FIFO pop)
      L1 (Focused)    — Priority Queue (highest effective_priority first)
      L2 (Background) — FCFS (FIFO pop)

    Ready Queue Implementation:
      Circular array (QUEUE_MAX = 32 entries per level).
      queue_push(), queue_pop_fifo(), queue_pop_priority().

    Priority Aging (Starvation Prevention):
    ───────────────────────────────────────
      • Every sched_tick(), wait_cycles increments for READY processes.
      • When wait_cycles >= AGING_THRESHOLD (5), effective_priority
        increases by AGING_STEP (1) each tick, capped at 20.
      • When a process is dispatched, wait_cycles resets to 0 and
        effective_priority resets to base_priority.
      • Every promotion is logged to the system log file.

    Adaptive Weight Vector:
    ───────────────────────
      Weights W = [w_burst, w_priority, w_age, w_io] are re-adjusted
      every SCHED_ADAPT_CYCLE (10) ticks based on:
        - High starvation  → boost w_age, reduce w_priority & w_burst
        - High ctx switches → boost w_burst, reduce w_io & w_priority
      Each weight is clamped to [0.05, 0.70] and re-normalised to sum=1.0.

    Dispatch Logic (sched_tick):
      1. Increment cycle, apply aging.
      2. Every 10 cycles, adapt weights.
      3. Pick next: try L0 first, then L1, then L2.
      4. Set chosen process to RUNNING, reset wait_cycles & effective_priority.
      5. Log dispatch event.

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  5.3  RESOURCE MANAGER  (resource_manager.cpp — 325 lines)             │
  └──────────────────────────────────────────────────────────────────────────┘

    Process Table:
      Fixed-size array of 32 PCB slots (MAX_PROCS = 32).
      Thread-safe via proc_table_mutex (pthread_mutex).

    Resource Tracking:
      Tracks current_ram_used / max_ram_mb and current_hdd_used / max_hdd_mb.
      Thread-safe via resource_mutex.

    Kernel Mood System:
      CALM       — RAM < 70%
      STRESSED   — RAM 70%-90%
      CRITICAL   — RAM >= 90%  (ALL new launches denied)
      Mood transitions are logged and printed.

    Grant/Deny Logic:
      resource_check()  — Verifies enough RAM+HDD; denies if CRITICAL mood.
      resource_commit() — Deducts resources from available pool.
      resource_release()— Returns RAM to pool (HDD persists on disk).

    IPC Handling:
      handle_resource_request() — Reads child's request, grants or denies,
      sends reply via pipe, updates PCB state, integrates with RAG for
      deadlock detection.

    System Logging:
      All events written to logs/neuralOS_log.txt with timestamps and
      current kernel mood.

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  5.4  MEMORY MANAGER  (memory.cpp — 267 lines)                         │
  └──────────────────────────────────────────────────────────────────────────┘

    Follows instructor-mandated E820 memory map pattern:
      • Simulated E820 table with 4 entries (low RAM, BIOS hole, extended
        RAM, ACPI region).
      • FreeRegion linked list built from usable E820 entries.
      • Page free_memory linked list of 4 KiB pages.

    Pre-allocated Pools (slab-style):
      • region_pool[64]  — FreeRegion nodes
      • page_pool[4096]  — Page nodes (up to 16 MiB addressable)

    API:
      init_memory(bytes)     — Builds E820, allocates backing store,
                                constructs free region and page lists.
      alloc_pages(n)         — Removes n pages from free list.
      free_pages(head)       — Returns page chain to free list.
      mem_alloc_mb(mb)       — MB-level wrapper around alloc_pages.
      mem_free_mb(head)      — MB-level wrapper around free_pages.
      mem_free_bytes()       — Counts free pages.
      mem_print_stats()      — Prints total/used/free memory.

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  5.5  PROCESS LAUNCHER  (process_launcher.cpp — 240 lines)             │
  └──────────────────────────────────────────────────────────────────────────┘

    Task Descriptor Table:
      18 tasks defined with: name, binary path, RAM, HDD, priority,
      archetype, and scheduler level.

    Launch Sequence (launch_task):
      1. Create two pipe pairs: kernel→child (k2c) and child→kernel (c2k).
      2. fork() the process.
      3. Child: sends RESOURCE_REQUEST via pipe, waits for GRANTED/DENIED.
         If GRANTED: execvp() the task binary (passes pipe FDs as argv).
         If DENIED: exits with code 1.
         If execvp fails: runs a built-in stub (200-500ms simulation).
      4. Parent: registers PCB, reads request, calls handle_resource_request,
         enqueues granted process into scheduler.

    Signal Handling:
      SIGCHLD handler — reaps zombie children via waitpid(WNOHANG),
      calls on_process_exit() to release resources.

    Shutdown:
      shutdown_all() — SIGTERM to all running processes, waits 2 seconds,
      then SIGKILL for any remaining. Final zombie reaping.

  ┌──────────────────────────────────────────────────────────────────────────┐
  │  5.6  DEADLOCK DETECTOR  (deadlock_detector.cpp — 254 lines)           │
  └──────────────────────────────────────────────────────────────────────────┘

    Resource Allocation Graph (RAG):
      Two resource types: RAM (id=0), HDD (id=1).
      holder[r]   — PID holding resource r (0 = free).
      waiters[r]  — Set of PIDs waiting for resource r.
      all_pids    — Union of all PIDs in the graph.
      Thread-safe via rag_mutex.

    Graph Encoding:
      Process nodes = (int)pid  (positive).
      Resource nodes = -(resource_id + 1)  (negative, e.g., RAM = -1).
      Edges: process→resource (request), resource→process (allocation).

    Cycle Detection Algorithm:
      Iterative DFS with 3-colour marking (white/grey/black).
      Back-edge to a grey node indicates a cycle (deadlock).
      Path reconstruction extracts the cycle members.

    API:
      rag_add_request(pid, res_id)     — Record a request edge.
      rag_add_allocation(pid, res_id)  — Record an allocation edge.
      rag_remove(pid)                  — Remove process from graph.
      detect_deadlock(cycle_pids)      — Returns true + involved PIDs if
                                          a cycle is found.

7. KEY OS CONCEPTS IMPLEMENTED
================================================================================

  7.1  Process Management
  ───────────────────────
    • Process creation via fork() + execvp()
    • PCB (Process Control Block) with 5 states: READY, RUNNING, BLOCKED,
      TERMINATED, ZOMBIE
    • Process table (32 slots, mutex-protected)
    • SIGCHLD-based zombie reaping via waitpid(WNOHANG)
    • Graceful shutdown: SIGTERM → wait → SIGKILL

  7.2  CPU Scheduling
  ───────────────────
    • Multi-Level Queue (3 levels) with different algorithms per level
    • Round Robin (L0), Priority with Aging (L1), FCFS (L2)
    • Priority Aging to prevent starvation (wait_cycles threshold)
    • Adaptive weight vector updated every 10 scheduler cycles
    • Background scheduler thread running at 100ms quantum

  7.3  Memory Management
  ──────────────────────
    • Simulated E820 memory map (matching real x86 BIOS conventions)
    • Page-based allocation (4 KiB pages)
    • FreeRegion linked list and Page free list
    • Slab-style pre-allocated pools (no malloc after init)
    • MB-level wrappers for kernel resource manager

  7.4  Inter-Process Communication (IPC)
  ──────────────────────────────────────
    • Bi-directional pipes: kernel↔child
    • Structured IPC_Message protocol (request, grant, deny, task_done)
    • Resource request/grant handshake before task execution
    • Pipe FDs passed as argv to execvp'd task binaries

  7.5  Resource Management
  ────────────────────────
    • RAM and HDD tracking with grant/deny enforcement
    • Kernel Mood system (CALM / STRESSED / CRITICAL)
    • CRITICAL mood blocks all new process launches
    • HDD usage persists (files on disk) while RAM is released on exit

  7.6  Deadlock Detection
  ───────────────────────
    • Resource Allocation Graph (RAG) with 2 resource types
    • Bipartite graph encoding (positive=process, negative=resource nodes)
    • Iterative DFS with 3-colour marking for cycle detection
    • Thread-safe graph mutations via mutex
    • Deadlock reported with list of involved PIDs

  7.7  Signal Handling
  ────────────────────
    • SIGCHLD — automatic zombie reaping
    • SIGTERM — graceful task shutdown (each task handles individually)
    • SIGKILL — forced termination during shutdown sequence
    • sigaction() used for reliable signal registration

  7.8  Synchronization
  ────────────────────
    • pthread_mutex for process table, resource pool, and RAG
    • pthread_create/detach for background scheduler thread
    • Volatile flags for cross-thread shutdown signalling

10. RUNTIME BEHAVIOR SUMMARY
================================================================================

  1. User runs: ./NeuralOS_X 1 10 2
  2. Boot animation displays (5 stages).
  3. Memory manager initialises (E820 map, page lists).
  4. Resource manager initialises (RAM=1024 MiB, HDD=10240 MiB).
  5. Scheduler initialises (3 empty queues, default weights).
  6. Background scheduler thread starts (100ms ticks).
  7. Task menu displayed; user enters commands at "NeuralOS>" prompt.
  8. Launching a task:
     a. fork() creates child process
     b. Child sends RESOURCE_REQUEST via pipe
     c. Kernel checks RAM/HDD/mood → GRANT or DENY
     d. If granted: child exec's the binary, kernel enqueues into scheduler
     e. If denied: child exits, deadlock check performed
  9. Scheduler continuously dispatches processes (L0 > L1 > L2 priority).
  10. Aging prevents starvation of lower-priority processes.
  11. On "shutdown": SIGTERM all tasks → wait → SIGKILL → goodbye.
